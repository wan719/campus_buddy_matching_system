### 1.2 技术实现要点

#### 功能1：博客文章 LocalStorage 持久化

实现思路：

- 将默认文章数据抽离到 `src/data/posts.js`，保证初始化数据独立管理。
- 新增 `src/storage.js` 封装 `loadPosts()` 与 `savePosts()` 方法。
- 页面首次访问时，如果 LocalStorage 中没有数据，则写入默认文章；后续访问直接读取本地保存的数据。
- 文章新增、编辑、删除后统一调用保存方法，保证刷新页面后数据不丢失。

关键代码片段：

```js
export function loadPosts() {
  const savedPosts = localStorage.getItem(STORAGE_KEY);

  if (!savedPosts) {
    savePosts(defaultPosts);
    return [...defaultPosts];
  }

  try {
    const parsedPosts = JSON.parse(savedPosts);
    return Array.isArray(parsedPosts) ? parsedPosts : [...defaultPosts];
  } catch {
    savePosts(defaultPosts);
    return [...defaultPosts];
  }
}
```

遇到的难点及解决：

- 难点：LocalStorage 只能保存字符串，直接保存对象会导致数据格式不正确。
- 解决方案：保存时使用 `JSON.stringify()`，读取时使用 `JSON.parse()`，并加入异常兜底，避免本地数据损坏导致页面报错。

#### 功能2：分类筛选、搜索与局部结果更新

实现思路：

- 在 `App` 类中维护 `selectedCategory` 与 `searchTerm` 两个状态。
- 通过 `getFilteredPosts()` 同时处理分类匹配和关键词匹配。
- 分类按钮点击后更新当前分类，并通过 CSS class 高亮当前选项。
- 搜索输入时只更新文章列表、结果数量和空状态提示，不再重建整个页面。

关键代码片段：

```js
updateResults() {
  const filteredPosts = this.getFilteredPosts();
  const resultsCount = document.querySelector('#resultsCount');
  const postsGrid = document.querySelector('#postsGrid');

  if (resultsCount) {
    resultsCount.textContent = `共 ${this.posts.length} 篇文章，当前显示 ${filteredPosts.length} 篇`;
  }

  if (postsGrid) {
    postsGrid.innerHTML = filteredPosts
      .map((post) => this.blogList.renderPostCard(post))
      .join('');
  }

  this.bindCardEvents();
}
```

遇到的难点及解决：

- 难点：最开始搜索框每输入一个字符就调用整页 `render()`，导致输入框节点被销毁再创建，出现“只按几下却输入更多字符”和删除异常的问题。
- 解决方案：将搜索逻辑改为局部渲染，只替换文章列表区域，不替换搜索框本身，从根源上避免输入事件和 DOM 重建互相影响。

### 3.2 典型问题深度分析

问题描述：

在测试搜索功能时，搜索框出现异常：只输入了少量字符，页面中却显示更多重复字符；同时使用删除键或清除按钮时也存在交互不稳定的问题。

问题分析：

最初实现中，搜索框的 `input` 事件每触发一次都会调用 `render()`，而 `render()` 会重新设置 `app.innerHTML`。这意味着每输入一个字符，搜索框 DOM 节点都会被销毁并重新创建。对于输入框这种高频交互元素，频繁重建会影响焦点、光标位置、输入状态与事件绑定，最终造成输入重复和删除异常。

解决过程：

1. 尝试1：在重新渲染后手动调用 `focus()` 恢复搜索框焦点（结果：只能缓解，不能从根本解决）
2. 尝试2：检查事件绑定逻辑和删除按钮逻辑，发现部分渲染后需要重新绑定卡片事件（结果：删除逻辑得到改善）
3. 最终方案：新增 `updateResults()`，搜索输入时只更新文章列表、结果数量和空状态，不再替换搜索框节点（结果：输入和删除均恢复正常）

经验总结：

前端开发中不能只关注“数据能不能更新”，还要关注“更新的范围是否合理”。整页重渲染实现简单，但容易影响输入框、滚动位置和事件绑定。后续遇到高频交互时，我会优先考虑局部更新，或者使用更成熟的前端框架来管理状态和渲染。
