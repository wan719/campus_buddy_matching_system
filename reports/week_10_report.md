### 1.2 技术实现要点

#### 功能1：待办状态管理与核心增删改

实现思路：

- 使用 `ref([])` 管理待办数组，单项结构为 `{ id, text, completed }`。
- 新增时读取 `newTodoText`，去除空白后写入数组并清空输入框。
- 删除时通过 `filter` 生成新数组，避免直接按下标操作导致状态混乱。
- 复选框通过 `v-model="todo.completed"` 双向绑定，直接驱动完成态展示。

关键代码片段：

```js
const todos = ref([
  { id: 1, text: '学习Vue 3', completed: false },
  { id: 2, text: '完成作业', completed: true }
]);

function addTodo() {
  const text = newTodoText.value.trim();
  if (!text) return;

  todos.value.push({
    id: Date.now(),
    text,
    completed: false
  });

  newTodoText.value = '';
}

function removeTodo(id) {
  todos.value = todos.value.filter((todo) => todo.id !== id);
}
```

遇到的难点及解决：

- 难点：输入框回车和点击按钮共用新增逻辑时，容易出现空字符串被提交。
- 解决方案：在 `addTodo()` 内统一做 `trim()` 与空值判断，只保留一处入口校验。

---

#### 功能2：未完成数量统计与页面响应式渲染

实现思路：

- 使用 `computed` 从 `todos` 推导未完成数量，避免手动维护计数状态。
- 通过 `v-for` 渲染待办项，`key` 使用 `id` 保证列表更新稳定。
- 通过条件类名与 `v-if/v-show` 控制空状态提示和完成态视觉反馈。
- 统计信息实时显示“剩余 X 项未完成”，与勾选状态自动同步。

关键代码片段：

```js
const incompleteCount = computed(() =>
  todos.value.filter((todo) => !todo.completed).length
);
```

遇到的难点及解决：

- 难点：一开始有把“剩余数量”写成普通变量，删除或勾选后存在显示不同步风险。
- 解决方案：改为 `computed` 派生数据，所有变更自动触发重新计算。

### 3.2 典型问题深度分析

问题描述：

在初版实现中，未完成数量曾尝试用普通变量记录。添加、删除、切换完成状态后，某些场景下统计值需要额外手动更新，逻辑容易漏改。

问题分析：

“剩余数量”本质上是由 `todos` 推导出的结果，不是独立状态。如果把它当成普通变量维护，就会出现多个代码路径都要改同一值，增加出错概率。

解决过程：

1. 尝试1：在新增、删除、勾选方法中分别修改计数变量（结果：可运行，但维护成本高）
2. 尝试2：梳理哪些字段是“源状态”、哪些是“派生状态”（结果：确认计数应为派生）
3. 最终方案：使用 `computed` 自动计算 `incompleteCount`（结果：统计逻辑稳定且更简洁）

经验总结：

在 Vue 中优先区分“源数据”和“派生数据”。凡是可由现有状态计算得到的数据，优先交给计算属性处理，能显著降低同步问题。
